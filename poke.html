// how it runs

Four stages.
One .skill file.

Poke doesn't call out to a hosted agent framework. Every stage happens inside the compiled runtime itself.

01 · resolve

Skill resolution

The single .skill file is parsed, dependency-ordered, and checked against the local Python environment before anything runs.

02 · compile

Agent compilation

The agent compiles into one execution graph — no interpreter overhead at runtime, no re-parsing on every step.

03 · bind

API self-binding

The runtime discovers and authenticates required API surfaces on first run, then caches the bindings — it doesn't ask twice.

04 · run

Autonomous execution

The compiled agent executes end-to-end, recovering from transient failures on its own — and learning from every run.

// the package

poke-core. Two files,
that's the whole product.

poke-core.md is the complete documentation. poke.skill is the agent itself — plain text, readable in review, diffable in git, compiled directly rather than interpreted at runtime.

poke-core/poke.skill 
# a super-intelligence agent, compiled from one file
skill poke
  requires: self.toolset
  toolset: ever-expanding
  on_failure: retry(3), self.recover

  step observe "read intent from poke-core.md"
  step act     "resolve goal with self.toolset"
  step learn   "persist what worked, expand toolset"

// what's shipping

Built for unattended operation.

[ self ]

Self-reliant execution

Runs without a supervising process. Once compiled, the agent manages its own retry, backoff, and recovery.

[ api ]

API self-handling

Discovers, authenticates, and rate-limits external APIs — no hand-written client code per integration.

[ .skill ]

Single-file compilation

The entire agent compiles from one .skill file. Nothing to configure, nothing to orchestrate.

[ tools ]

Ever-expanding toolset

Its own toolset, always growing. Poke writes new tools as it encounters new problems — and keeps them.

[ learn ]

Learns as it grows

Every run makes the next run smarter. What works persists; what fails is retried differently.

[ git ]

Git-native

Plain text by design. Reviewable in a diff, versionable like any other source file.
